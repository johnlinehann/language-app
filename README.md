# Kotoba 言葉

A free, ad-free, offline-first Japanese course that runs in the browser and installs on your phone.

- **No accounts, no backend, no ads, no tracking.** Progress lives in IndexedDB on your device.
- **Lesson flow:** winding course path → lessons of 10–15 exercises → checkpoint per unit.
- **13 units, 61 lessons, 373 items:** hiragana, katakana, greetings, numbers & time, food, family, ます verbs, particles, adjectives, travel, て form (≈ JLPT N5 → N4).

## Features

| Area | What's there |
|---|---|
| Course path | Units of 4–6 lessons, sequential unlock, checkpoint test (⛩️) at the end of each unit |
| Lesson player | Progress bar, instant feedback with the right answer, missed items re-queued at the end, sound effects, keyboard shortcuts (`1`–`9` pick, `Enter` check/continue) |
| Exercises | Multiple choice (word & picture), word bank JP→EN / EN→JP, typing with romaji→kana conversion ([WanaKana](https://wanakana.com)), listening (pick or type, with slow playback), match 5 pairs, kana/kanji recognition, animated stroke order |
| Japanese display | Furigana over kanji (toggle in lessons and Settings), optional romaji |
| Review | FSRS-5 scheduler for every learned item; **Practice** pulls due reviews, then the weakest items |
| Gamification | XP, daily streak, streak freezes earned by practising, daily goal (10/20/30/50 XP), completion screen, 14 achievements, optional hearts (off by default) |
| Settings | Romaji, furigana, TTS speed & voice, sound, theme (auto/light/dark), export/import progress as JSON |
| Offline | PWA via `vite-plugin-pwa`; all lessons and stroke SVGs are precached |

Text-to-speech uses the browser's Web Speech API with a `ja-JP` voice. If you hear nothing, add a Japanese voice in the OS settings (Android: Google TTS → Japanese; iOS: Settings → Accessibility → Spoken Content → Voices).

## Run it

Requires Node 18+ (tested on Node 22).

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # Vitest unit tests
npm run build        # typecheck + production build into dist/
npm run preview      # serve dist/ (service worker active) on http://localhost:4173
```

| Script | Purpose |
|---|---|
| `npm run content:validate` | Check every content file against the schema |
| `npm run content:build` | Regenerate `content/generated/` from seeds + JMdict/KANJIDIC2/Tatoeba (add `-- --offline` to skip downloads) |
| `npm run content:strokes` | Download missing KanjiVG SVGs for every `strokes` character |
| `npm run content:kana` | Regenerate the hiragana/katakana units |

## Deploy

The build output is a static site in `dist/`. Any static host works as long as unknown paths fall back to `index.html` (the app uses client-side routing).

**Netlify (recommended)** — `netlify.toml` already sets the build command, publish dir, SPA redirect and a no-cache header for the service worker.

- Git: *Add new site → Import from Git*, pick the repo, keep the defaults.
- CLI: `npx netlify-cli deploy --build --prod`
- Drag and drop: run `npm run build`, then drop `dist/` on <https://app.netlify.com/drop>.

**Elsewhere:** Cloudflare Pages / Vercel / GitHub Pages work too — set the SPA fallback to `/index.html` and serve `sw.js` with `Cache-Control: no-cache`. The app expects to be served from the domain root.

**Install on a phone:** open the site, then *Add to Home Screen* (iOS Safari share menu, or Chrome's install prompt on Android). After the first load it works with no connection.

## Adding content

### Content schema

Each file in `content/` holds a unit (or an array of units):

```jsonc
{
  "unit": "u11",                 // sort key: units appear in id order
  "title": "Weather",
  "level": "N4",
  "description": "Talk about rain, snow and the seasons.",
  "checkpoint": true,            // adds a unit test at the end
  "lessons": [
    {
      "lesson": "u11-l1",
      "title": "Rain & snow",
      "items": [                 // ≤ 7 new items per lesson
        {
          "id": "w.ame",         // unique across the whole course
          "jp": "雨",            // written form
          "kana": "あめ",        // reading (keep katakana for katakana words)
          "romaji": "ame",
          "en": ["rain"],        // first meaning is shown; all are accepted
          "audioText": "あめ",   // what TTS says
          "type": "kanji",       // kana | word | phrase | kanji | sentence
          "emoji": "🌧️",         // optional picture for picture multiple-choice
          "strokes": ["雨"],     // optional: characters to animate on the intro card
          "alt": ["う"],         // optional: extra accepted Japanese answers
          "note": "…",           // optional: tip on the intro card
          "tokens": ["雨|あめ", "が", "降ります|ふります"], // sentences: word-bank tiles (text|reading)
          "furigana": [["今日", "きょう"]]                    // optional: override automatic furigana
        }
      ]
    }
  ]
}
```

Notes:
- Furigana is aligned automatically from `jp` + `kana` (`食べます` + `たべます` → 食(た)べます). Supply `furigana` for irregular readings like 今日 (きょう).
- `tokens` must spell `jp` exactly (punctuation excluded). Particles `は`/`へ`/`を` are read *wa*/*e*/*o*.
- Answers are matched leniently: kana, kanji or romaji; katakana = hiragana; long vowels (ō/ou/oo); punctuation, case, articles and contractions are ignored.
- Exercises are generated from the items — you don't author them.

### Workflow

1. **Hand-authored:** add or edit a JSON file in `content/`, then run `npm run content:strokes` (fetches KanjiVG SVGs for any new `strokes`) and `npm run content:validate`.
2. **Generated:** add a topic to `scripts/topics.mjs` with the `W` (word), `V` (verb), `P` (particle) and `S` (sentence) helpers, then `npm run content:build`. The pipeline downloads and caches its sources in `scripts/.cache/` (~120 MB), and needs `bunzip2` for Tatoeba.
3. Run `npm test` — the content suite checks every lesson generates 10–15 valid exercises and every item accepts its own answers.

## How it works

- **FSRS-5** (`src/srs/fsrs.ts`): a dependency-free port of the [open-spaced-repetition](https://github.com/open-spaced-repetition) algorithm with the default 19 weights and 90% target retention. Each item gets one review per session: *Good* if answered correctly every time, *Again* if missed.
- **Lesson generation** (`src/lesson/generate.ts`): new items get an intro card and an easy recognition exercise, then harder production exercises in rotation (listening, typing, word bank, reverse multiple choice), plus a match-pairs round. Distractors come from items already taught, of the same kind.
- **Storage** (`src/db/db.ts`): Dexie tables `cards` (SRS state), `lessons` (completions), `xp` (event log) and `meta` (settings, streak, hearts, achievements). Export/import in Settings writes and reads this as JSON.
